\section{Εκτελεστική Σύνοψη}
% ================================================================

Η παρούσα αναφορά τεκμηριώνει την πλήρη αρχιτεκτονική, τις αποφάσεις
σχεδιασμού, την τρέχουσα κατάσταση και το εναπομένον έργο της
υλοποίησης LightRAG στο πρόγραμμα δίκαιης σύγκρισης RAG
αρχιτεκτονικών. Η υλοποίηση ακολουθεί αυστηρά το πλαίσιο
\texttt{CONTROLLED\_ADAPTATION}: η architecture-defining λογική του
κατασκευαστή παραμένει ακέραιη, ενώ μόνο infrastructure-level
components (embeddings backend, storage persistence, LLM
provider) αντικαθίστανται με τεκμηριωμένη και αναστρέψιμη
διαδικασία.

\begin{keybox}
\textbf{Τρεις αμετάβλητοι στόχοι} που καθοδηγούν κάθε απόφαση:
\begin{enumerate}[nosep]
  \item \textbf{Ακαδημαϊκή ορθότητα}  κάθε αποτέλεσμα να αντέχει
        κριτική επιτροπής.
  \item \textbf{Δικαιοσύνη σύγκρισης}  κοινό dataset envelope, κοινός
        embedder (BGE-M3 rev \texttt{5617a9f6}), κοινό query set,
        κοινή ground-truth projection.
  \item \textbf{Διατήρηση γνησιότητας}  ουδεμία αλλαγή σε prompts,
        chunker, graph semantics.
\end{enumerate}
\end{keybox}

\section{Αρχιτεκτονική LightRAG  Native Σημασιολογία}
% ================================================================

\subsection{Upstream Pipeline}

Η native LightRAG εκτελεί την εξής ακολουθία:

\begin{enumerate}[nosep]
  \item \textbf{Chunking}  fixed-token F-strategy, default
        \texttt{chunk\_token\_size=1200},
        \texttt{chunk\_overlap=100}, μέσω του
        \texttt{chunking\_by\_token\_size}.
  \item \textbf{Entity extraction}  LLM call ανά chunk, με
        delimiter-based output (\texttt{<|\#|>} και
        \texttt{<|COMPLETE|>}).
  \item \textbf{Relation extraction}  ίδιο LLM call, δύο περάσματα
        (gleaning).
  \item \textbf{Entity/relation description merge}  LLM summarization
        για deduplication.
  \item \textbf{Graph persistence}  NetworkX GraphML.
  \item \textbf{Vector persistence}  NanoVectorDB για entities,
        relations, chunks.
  \item \textbf{Query}  keyword extraction (LLM) $\rightarrow$
        hybrid retrieval $\rightarrow$ context construction.
\end{enumerate}

\subsection{B1 Thin Infrastructure Wrapper}

Ο B1 wrapper \emph{δεν αλλάζει} το underlying generation. Προσθέτει
μόνο:

\begin{itemize}[nosep]
  \item Checksum-bound immutable cache
  \item Token/request accounting
  \item Single identical retry
  \item Failure logging
\end{itemize}

\begin{warnbox}
Ο wrapper \textbf{MUST NOT} αλλάζει:
\begin{itemize}[nosep]
  \item Prompt
  \item System prompt
  \item History messages
  \item Generation parameters (temperature, max\_tokens, \ldots)
  \item Parsing delimiters
  \item Output text
\end{itemize}
\end{warnbox}

Δύο cache modes:
\begin{itemize}[nosep]
  \item \texttt{INDEXING}  Cache miss $\rightarrow$ live inference,
        write cache, return.
  \item \texttt{REPLAY}  Cache miss $\rightarrow$ \texttt{CacheMissError},
        no live inference. Αυτό είναι το query-time benchmark mode.
\end{itemize}

\subsection{Cache Key Συνιστώσες}

\begin{equation*}
\text{key} = \text{SHA256}\Bigl(
  \text{repo\_id} \,\|\, \text{revision} \,\|\,
  \text{tokenizer\_revision} \,\|\,
  \text{prompt}^{\text{SHA}} \,\|\,
  \text{system}^{\text{SHA}} \,\|\,
  \text{history} \,\|\,
  \text{decoding\_config}
\Bigr)
\end{equation*}

Οποιαδήποτε αλλαγή δημιουργεί νέο namespace. \textbf{Ποτέ} overwrite
ή silent reuse (E5 ACK).

\subsection{Token Ceiling}

\begin{itemize}[nosep]
  \item Hard ceiling: 50,000,000 tokens (input + output)
  \item Stop new atomic unit at 95\%
  \item Failure rate threshold: 1\%
  \item On exceed: \texttt{BLOCKED\_ON\_TOKEN\_CEILING}
\end{itemize}

\section{Ακαδημαϊκή Τοποθέτηση}
% ================================================================

\subsection{Γιατί η προσέγγιση είναι ακαδημαϊκά έντιμη}

\begin{enumerate}
  \item \textbf{Ρητή σήμανση controlled adaptations}: Κάθε
        αντικατάσταση φέρει label \texttt{CONTROLLED\_ADAPTATION} και
        τεκμηρίωση σε YAML.
  \item \textbf{Αμετάβλητο native pipeline}: Οι 14 architecture-defining
        συνιστώσες παραμένουν ακριβώς όπως στον κατασκευαστή.
  \item \textbf{Deterministic reproducibility}: Checksums, pinned
        revisions, atomic writes, frozen configs.
  \item \textbf{Two-track design}: Track 1 (controlled comparison) με
        κοινό embedder. Track 2 (native-fidelity) ρητά
        \texttt{DEFERRED\_WITH\_REASON} λόγω αδυναμίας offline reproduction.
  \item \textbf{No silent substitutions}: Κάθε failure που δεν
        απαντιέται από source οδηγεί σε escalation, όχι εικασία.
  \item \textbf{Hard failure semantics}: Cache miss σε REPLAY mode
        σημαίνει σκληρό fail, όχι heuristic fallback.
\end{enumerate}

\subsection{Controlled Adaptation  Τι Σημαίνει Πραγματικά}

\begin{keybox}
\textbf{Controlled adaptation} = αντικατάσταση infrastructure-level
component με \emph{αποδεδειγμένα ισοδύναμο} (semantic equivalence)
υποκατάστατο, με:
\begin{itemize}[nosep]
  \item Ρητή τεκμηρίωση της αντικατάστασης
  \item Fidelity risk classification (LOW/MEDIUM/HIGH)
  \item Validation requirement
  \item Amendment record
\end{itemize}
\textbf{Δεν} σημαίνει ελεύθερη τροποποίηση του pipeline.
\end{keybox}

χρειάζεται ρητή ερμηνεία (native-stack vs isolated-architecture).
\end{warnbox}

\begin{warnbox}
\textbf{2. Colab Transfer Protocol}

Πρέπει να υλοποιηθεί LightRAG-specific runner και schemas (Q41=C),
βασισμένα στο architecture-neutral envelope του LongRAG.
\end{warnbox}

\textbf{3. Evaluation Pipeline}

Ground-truth projection per dataset και per-query metrics
(Precision, Recall, Hit, nDCG, MRR) με per-dataset macro
aggregation. Den εξαρτάται από LLM.
\end{warnbox}
